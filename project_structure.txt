SYNCHRONIZED BRANCHES MANDATE
----------------------------
CRITICAL: The software is maintained as two functional branches from a SINGLE codebase:
1. Branch 1: Native (Windows OCR Engine, zero OCR dependencies) -> FreeSnip.exe
2. Branch 2: Compiled with bundled Tesseract external OCR engine (LTS/Offline) -> FreeSnip_tesseract.exe

ENGINEERING STANDARD:
Every change (UI, logic, timers, overlay effects, editing tools) MUST be applied to both branches simultaneously.
Agents MUST ensure that features remain 100% synchronized between branches, except for the underlying OCR engine implementation itself.
Both branches utilize the high-performance SixLabors.ImageSharp pipeline for image manipulation and OCR pre-processing.

GOAL & PURPOSE
--------------
FreeSnip is a professional-grade, ultra-fast screen capture and OCR tool optimized for .NET 9 Native AOT in the Windows OCR branch.
It serves users who need rapid imaging workflows with 100% privacy (zero cloud dependencies).
The application follows a "Ghost" philosophy: it stays out of sight until triggered, performs tasks with sub-millisecond responsiveness, and stays fully local. The Native branch is dependency-free for OCR; the Tesseract branch bundles local external OCR files.

PRIMARY ARCHITECTURAL INVARIANTS & CORE MANDATES (THE "GHOST" RULES)
-------------------------------------------------------------------
1. **Zero UI Friction:** Tray icon click triggers capture immediately. No splash screens.
2. **Non-Destructive Vector Annotations & Avalonia/ImageSharp Pipeline:** The active UI and image pipeline is Avalonia UI + SixLabors.ImageSharp. Vector annotations (Arrows, Lines, Rectangles, Ellipses, Text boxes, Counters, Emojis, Pasted Images, and Polylines) MUST NEVER be destructively baked or flattened into the background image during in-editor operations (Crop, Slice Cutout, Move, Rotate, Resize, or Tool Switching). Raster modifications mutate background image bounds while vector annotations are mathematically transformed and preserved as selectable, movable, and editable vector controls, with full pre-operation snapshotting (SaveUndoState(cloneImage: true)) guaranteeing complete Ctrl+Z undo/redo recovery. Legacy compatibility names and shims may remain for migration support.
3. **SVG Toolbar UI:** The Editor uses bundled SVG toolbar icons and standard text/icon controls.
4. **Thin-Client Interop:** Use direct Win32 P/Invoke calls (freesnip.foundation.Interop.Win32Interop / freesnip.native.PInvoke) for performance, bypassing "heavy" .NET wrappers.
5. **Native Finality:** Branch 1 is compiled to machine code via .NET 9 Native AOT (FreeSnip.exe). Branch 2 uses a Native AOT installer wrapper with a self-contained non-AOT Tesseract payload (FreeSnip_tesseract.exe) because the external OCR runtime is not Native AOT-compatible.
6. **Async Everything (Engine Audit Parity):** All I/O, OCR, and cleanup operations MUST be non-blocking. 
   - No `Thread.Sleep`. Use `Task.Delay`.
   - No `.Result` or `.Wait()`. Use `await` or `IAsyncDisposable` / `DisposeAsync`.
   - Both OCR engines must validate required language packs (EN/HE) before execution.
7. **One-Click Sequential Finality (Zero Prompts) & Resilient Save Pipeline:** The editor core is "Zero-Dialog". Fast default save writes immediately without showing any save dialog when the destination is valid.
   - **Destination Hierarchy:**
     1. `CoreConfiguration.UserDownloadPath` (if configured and writable).
     2. `KnownFolders.GetDownloadsPath()` (standard Windows shell Downloads location).
     3. Lightweight probe validation (`IsDirectoryWritable`) probes target directory with a temporary probe file before saving.
     4. **Resilient Path Fallback:** If the primary destination is missing, offline (e.g. offline OneDrive redirection, unmapped network drives), or unwritable, prompt the user ONCE with native folder picker (`StorageProvider.OpenFolderPickerAsync`: "FreeSnip: Select Default Save Folder"). If chosen, persist path to `UserDownloadPath` in `freesnip.ini` for all future saves without prompting again. If cancelled or failed, save to `%TMP%\FreeSnip\` and display toast notification: `"Saved to FreeSnip Temp Folder (Downloads unavailable)"`.
   - **Predictable Context-Aware Clipboard Invariant:** Saving an image (Ctrl+S or Save button) writes strictly to disk and 24-hour backup (if enabled), leaving the Windows clipboard 100% untouched to avoid destroying whatever data the user previously held on the clipboard. Keyboard shortcut `Ctrl+C` inside the editor is strictly context-aware: it copies extracted OCR text when in OCR mode with words selected, copies the selected annotation object into internal memory buffer `_annotationClipboard` when an object is selected, and does nothing when nothing is selected (preventing accidental clipboard overwrites). The Toolbar "Copy" button explicitly copies the flattened image to the clipboard. The Toolbar "Download" button executes a double-clipboard sequence: stages `CF_DIB` image format onto the clipboard, probes it to guarantee availability, and immediately afterwards stages plain text only wrapped in quotation marks `"{downloadedFilePath}"` onto the clipboard.
   - By default on fresh installations, automatic editor closing is enabled (`CoreConfiguration.CloseEditorOnAction` default = `true`). The editor window automatically closes following the notification overlay duration (NotificationOverlayDurationMs, clamped to 250-1000ms). When `CloseEditorOnAction` is explicitly disabled by the user in Settings (or preserved as-is during upgrade migration), the editor remains fully open, interactive, and focused after Save, Copy, or OCR, preserving zoom, pan, active selections, and the undo/redo stack:
     - "Save Image" (Ctrl+S): Saves image (PNG by default; 100% JPEG if configured) to file without modifying the Windows clipboard, and saves a 24-hour backup (matching the configured format) to `%TMP%\FreeSnip\` when backup is enabled.
     - "Download Button" (Toolbar Download / SaveToDownloadsAsync): Saves image file to user downloads directory (or `%TMP%\FreeSnip\` fallback), stages `CF_DIB` image format onto the clipboard, probes it to prevent race conditions, and immediately afterwards stages plain text only wrapped in quotation marks `"{downloadedFilePath}"` onto the clipboard (probed via `CF_UNICODETEXT`).
     - "Copy to Clipboard":
       - Keyboard shortcut (`Ctrl+C`): Context-aware routing:
         - Tier 1 (Static OCR Mode): If text is marked, extracts visual selection text, copies to clipboard via `UiClipboard.SetTextAsync()`, and shows toast "TEXT COPIED" without closing editor.
         - Tier 2 (Canvas Object Selected): Deep-clones object properties synchronously into in-memory clipboard buffer `_annotationClipboard`, and displays toast "OBJECT COPIED" without touching the Windows clipboard or closing window.
         - Tier 3 (Nothing Selected): No-op. Does not overwrite the Windows clipboard.
       - Toolbar "Copy" button: Copies flattened image to clipboard via `UiClipboard.SetImageAsync()`, displays toast "IMAGE SAVED TO CLIPBOARD", and closes or preserves window lifecycle depending on `CloseEditorOnAction`.
     - "OCR": Copies text to clipboard, saves `.txt` to `%TMP%\FreeSnip\` when backup is enabled, and opens it in Notepad.
   - **Context-Aware Paste (Ctrl+V):** When an annotation object or multi-select group is held in the in-memory clipboard buffer (`_annotationClipboard`), duplicates it instantaneously (0ms latency) offset by (+20, +20) DIPs from the copied source (clamped to canvas bounds), adds to AnnotationCanvas, selects it, updates indicators, and pushes an undo snapshot without querying the OS clipboard or triggering native image decoding. Falls back to external clipboard image paste only when no annotation is buffered or when an external image was copied while the editor window was deactivated.
8. **PNG-Default Output with Optional JPEG (100% Quality):**
   - PNG ingestion is allowed (opening files or injecting from clipboard).
   - ALL image output (manual saves, 24-hour backup, automated history) defaults to `.png` (lossless, full 32-bit ARGB alpha transparency preserved).
   - Users may switch to JPEG via the "Output Image Format" selector in Settings. JPEG is ALWAYS encoded at 100% quality — no sub-100 lossy output is ever permitted.
   - Alpha transparency is never composited to a solid background unless the user has explicitly chosen JPEG output.
9. **Automated 24-Hour Retention:**
   - **Immediate Raw Backup:** When backup is enabled, every capture (region, full, window) immediately saves a raw backup (PNG by default; JPEG at 100% quality if the user configured JPEG) to `%TMP%\FreeSnip\` before any editing begins.
   - All enabled backup artifacts (images, text) purged from `%TMP%\FreeSnip\` after 24 hours.
   - Cleanup task runs on startup and every 4 hours to purge the `%TMP%\FreeSnip\` directory of expired files.
10. **Folder Structure Mandates:**
   - Persistent Install: `C:\Program Files\FreeSnip\`
   - Persistent Logs: `%PROGRAMDATA%\FreeSnip\`
   - User Config: `%AppData%\FreeSnip\` (`freesnip.ini`)
   - Local App Data: `%LocalAppData%\FreeSnip\`
   - Upgrade Staging Backups: `%LocalAppData%\FreeSnipUpgradeBackups\[timestamp]\`
   - **Unified Temporary Root:** `%TMP%\FreeSnip\`
     - All user-initiated saves, background snapshots, and OCR outputs MUST use this path for 24-hour retention.
     - Subfolder `\Lifecycle\`: Used for installer unpacking and self-cleanup.
     - Subfolder `\Runtime\`: Used for transient DLL extraction.
   - **Installation Log:** Saved EXCLUSIVELY to a standalone file at `%TMP%\FreeSnip_Installation.log`.
11. **Visual Notification Overlays:**
   - Any successful download or OCR action MUST trigger a **blinking 4-color high-contrast overlay** (#FFFFFF, #FF3355, #00D2FF, #FFB703) honoring configurable duration (NotificationOverlayDurationMs in INI, clamped 250-10000ms, default 1.0s / 4 cycles).
   - Text variants: "IMAGE SAVED TO DOWNLOADS", "IMAGE SAVED TO CLIPBOARD", "TEXT COPIED", "TEXT COPIED & SAVED", and "SAVED TO FREESNIP TEMP FOLDER".
12. **Single-Instance IPC Relay & Foreground Delegation:** When FreeSnip is already running in the background tray, secondary instance launches (`FreeSnip.exe`) delegate foreground activation rights via Win32 `AllowSetForegroundWindow(ASFW_ANY = -1)` and transmit commands (`ACTIVATE` or `OPEN_FILE:<path>`) over the named pipe `Local\FreeSnip_Instance_IpcPipe`. The background instance immediately surfaces (focusing `ImageEditorWindow`, opening the targeted image, or focusing `SettingsWindow`) while the secondary instance exits cleanly with code 0 without crashing or prompting.
13. **Fail-Safe Upgrade & Deployment Engine:**
   - **Phase 1: Probe, Stage & Verify:**
     1. Instance Detection: Inspect running FreeSnip processes (`FreeSnip.exe`, `FreeSnip_tesseract.exe`), directory presence (`C:\Program Files\FreeSnip\`), config existence (`%AppData%\FreeSnip\freesnip.ini`), and task registration (`schtasks /Query /TN "FreeSnip"`).
     2. Durable Settings Backup: Copy existing `freesnip.ini` into `%LocalAppData%\FreeSnipUpgradeBackups\[timestamp]\`, verified with SHA-256 hash.
     3. Shadow Staging: Unpack updated FreeSnip binaries to `C:\Program Files\FreeSnip\` while background instances remain running. Probe binary execution via `"C:\Program Files\FreeSnip\FreeSnip.exe" --test-probe`.
     4. Critical Abort Guard: If any file check, AV interference, extraction, or probe fails, abort immediately, purge staged updates, and maintain current running instance untouched.
   - **Phase 2: Atomic Switchover:**
     1. Process Handover: Request running FreeSnip processes to close cleanly via IPC/`WM_CLOSE` (with a 3-second timeout before termination).
     2. Register FreeSnip Anchors: Register Start Menu shortcut (`FreeSnip.lnk`), shell file associations (ProgID: `freesnip.editor.1`, "Open with FreeSnip"), uninstall key (`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\FreeSnip`), app keys (`HKLM\SOFTWARE\FreeSnip`, `HKCU\SOFTWARE\FreeSnip`), and autostart task or Run key.
     3. Footprint Cleanup: Purge obsolete temporary files and logs in `%TMP%\FreeSnip\`.
     4. Launch FreeSnip: Start `"C:\Program Files\FreeSnip\FreeSnip.exe"` in the active user session.

UI/UX ACCESSIBILITY & LAYOUT MANDATES
-------------------------------------
1. **Named For Assistive Tech:** Every interactive control carries `AutomationProperties.Name`. Icon-only buttons must never ship unnamed.
2. **Minimum Target Size:** No interactive control is smaller than 24x24 (`FreeSnipMinTouchTarget`), per WCAG 2.2 SC 2.5.8.
3. **Single Dialog Implementation:** All confirmations go through `freesnip.editor.helpers.ConfirmDialog` - design-system colours, Escape to cancel, focus starting on the safe option. In-window prompts must disable the content behind them and move focus inside.
4. **Destructive Actions Confirm:** Clear All, Reset All Hotkeys and discarding unsaved Settings or editor changes all confirm first, stating what is lost.
5. **Tokens Only:** Colours, fonts and sizes come from `DesignSystem.axaml`. Brush properties bind to `*Brush` keys, never to `*Color` keys. No literal hex in window markup.
6. **Elastic Layout:** Labels, inputs and buttons use `MinWidth`/`MinHeight`, never fixed `Width`/`Height`, so DPI scaling and longer strings cannot clip text. Every resizable window declares `MinWidth`/`MinHeight`.
7. **RTL Ready:** Every window calls `UiLayoutDirection.Apply(this)`, which mirrors the chrome when `CoreConfiguration.Language` is a right-to-left locale. String translation still requires `language_*.xml` catalogues for `freesnip.foundation.core.Language`; none ship today, so the chrome is English-only until they are authored.
8. **One Icon, One Meaning:** No icon asset is reused for two different actions, and icons within a row share one size (24px in toolbars, 16px in the tray).
9. **LOCKED UI SPECIFICATION - PERMANENT AND IMMUTABLE - DO NOT ALTER (Line Thickness Quick Buttons Geometry):** The bottom pane quick line thickness buttons in `ThicknessChoicesPanel` are permanently locked to exact button widths: Tag 1 = 10px, Tag 2 = 11px, Tag 3 = 12px, Tag 5 = 15px, Tag 8 = 18px, Tag 12 = 22px, Tag 16 = 26px, with `Margin="0"`, `Spacing="0"`, and `FlowDirection="LeftToRight"`. This geometry provides a human-eye symmetrical progression. Modifying, recalculating, or tampering with these dimensions or spacing is strictly prohibited for all AI agents and developers.

FUNCTIONAL SPECIFICATIONS (THE USER EXPERIENCE)
-----------------------------------------------
1. **Hotkey Triggers:**
   - `PrintScreen`: Starts custom rubberband region selection.
   - `Alt + PrintScreen`: Captures EXACTLY the current active window/app size only.
   - `Ctrl + PrintScreen`: Captures the entire virtual desktop / fullscreen.
   - `Shift + PrintScreen`: Repeats capture of the last selected region.
   - **High-Compatibility Copy:** Every capture is AUTOMATICALLY pushed to the clipboard synthesizing `CF_DIB`, `CF_DIBV5` (with alpha channel bitmasks), and registered `PNG` format, preserving 32-bit ARGB alpha transparency while remaining compatible with legacy Win32 apps.
2. **Visual Feedback & Collision Mechanics:**
   - Systray Icon: Turns **RED** immediately upon entering capture mode. Returns to **BLUE** when finished.
   - **Intelligent Cursor Dodging:** On-screen instruction banners actively calculate bounding-box collisions and jump away from the mouse cursor to ensure the capture area is never obstructed.
3. **Unified Magnifier Engine:**
   - Shared circular UI style for both region selection and color sampler.
   - **Smart-Flip Region Selection:** Lens stays 30px diagonally away from cursor, "flipping" quadrants to avoid covering the capture area. 2x zoom.
   - **Color Sampler Magnifier:** Fixed-center logic with 8x zoom, live hex label, precise red crosshair, and full multi-monitor support.
4. **Magnetic Rubberband Snapping:**
   - Cursor over window triggers a high-visibility **Blue Highlight Border** snap with a strict **10-pixel proximity threshold**.
   - Initiating the rubberband selection directly on a window title area renders a dynamic "ghost effect" preview.
   - Coordinate accuracy is 100% DPI-aware, applying `RenderScaling` to logical Avalonia coordinates.
5. **OCR Painter Mode & Preemptive Caching (The "T" Toggle):** - Hitting `T` during selection toggles "OCR Painter" mode.
   - **Preemptive Background Execution:** Toggling the mode instantly triggers silent OCR across the entire virtual desktop before the region is drawn, guaranteeing zero-latency text extraction upon selection release.
6. **In-Editor OCR:** Clicking OCR symbol extracts text, copies to clipboard, opens Notepad, and saves `.txt` to `%TMP%\FreeSnip\`. Closes the editor window automatically by default following notification overlay (or keeps it open and focused when `CloseEditorOnAction` is disabled).
7. **Intelligent Editor Display:** Implements parallelSniplets, Cascading Positioning, Majority Monitor Centering, and Adaptive Sizing to ensure non-overlapping, context-aware window placement across multiple displays.
8. **Save Workflow (single vocabulary):** The action is named "Save" everywhere - button, tooltip, Settings and accessibility name; only the completion overlay names the destination ("IMAGE SAVED TO DOWNLOADS" or "IMAGE SAVED TO FREESNIP TEMP FOLDER"). Clicking "Save" (or pressing Ctrl+S) writes a PNG (or 100% JPG if configured) following the destination hierarchy (`UserDownloadPath` -> Shell `Downloads` -> One-time picker -> `%TMP%\FreeSnip\`), leaving the Windows clipboard 100% untouched to avoid destructive side effects or overwriting previous user clipboard content, saves a temp backup when enabled, displays the notification overlay (plus toast if fallen back to temp), and closes the window automatically by default following the notification overlay (bypassing close and preserving viewport, zoom, selection, and undo stack when `CloseEditorOnAction` is disabled). Canvas items are called "objects" in every surface (tooltip, confirmation, delete button).
9. **Shell "Open With" Integration (Secondary Instance Routing):** Right-clicking any image format in File Explorer and choosing "Open with FreeSnip" routes the target image path. If FreeSnip is already running in the background tray, the secondary instance transfers foreground rights (`AllowSetForegroundWindow`) and relays `OPEN_FILE:<path>` over `Local\FreeSnip_Instance_IpcPipe` to the primary instance, which opens the file in a new Editor window and brings it to the front before the secondary instance cleanly exits with code 0. If FreeSnip is not currently running, it launches the Editor directly, bypassing Tray Icon initialization. Outputs from this workflow are saved according to the configured format (PNG default with full alpha transparency, or 100% JPEG if configured).

TASK IMPLEMENTATION LOG (BUGFIXES & FEATURES)
---------------------------------------------
1. Toolbar State Persistence: Added SnapToggleBtn in BottomToolbarBorder in ImageEditorWindow.axaml. Wired up OnSnapToggleClick and bound to CoreConfiguration.MagneticSnappingEnabled in ImageEditorWindow.axaml.cs.
2. Magnetic Snapping Extension: Updated ApplyMagneticSnap and GetMagneticSnapTargets in ImageEditorWindow.axaml.cs to support all shapes.
3. Diagram Snapping: Replaced PasteSnap logic with SnapAxisEdge for vector points in ImageEditorWindow.axaml.cs.
4. Alternating Snap Suppression: Initial drag state-machine implementation (superseded by Fix 29 always-on magnetic snapping).
5. Duplication Cursor Fix: Updated OnDuplicateClick to reset _currentTool and set Cursor to null on cloned shape in ImageEditorWindow.axaml.cs.
6. Scaling Decoupling: Refactored ResizeSelectedControl to decouple Left/Top translation from sizing constraints for proportional scaling in ImageEditorWindow.axaml.cs.
7. Cross-Monitor Rubberband (root cause): CaptureHelper.CaptureRegionAsync used to spawn ONE CaptureWindow PER MONITOR, each owning its own frozen crop and coordinate space, so the rubberband, magnifier lens and window-snapping all stopped dead at every monitor border; a selection crossing screens had to be released and restarted. Fix: a single borderless overlay now spans the entire virtual desktop (bounds union), fed by one unified frozen backdrop (per-monitor 3px navy outlines are drawn directly into the clone via DrawMonitorFrame), and CaptureWindow.ToScreenPixels/ToScreenRect now map DIPs to absolute device pixels via PointToScreen, which stays correct on mixed-DPI multi-monitor setups.
8. Red-Eye Tray Icon (root cause): App.ForceRedTrayIcon(false) is reachable ONLY through CaptureWindow.EndCaptureSession (BeginCaptureSession flips the icon red and arms the _captureTrayIconHeld guard). Any capture abort path that returned early - null snapshot, empty screen enumeration, zero overlays, or an exception before the overlays were shown - skipped the End call and left the tray icon stuck red for the rest of the session. Fix: every early-exit in CaptureHelper (and the exception fallback) now calls EndCaptureSession; CaptureWindow.OnClosed re-arms it if !_captureCompleted, and the ISSUE_005 overlay-close wait bounds the final release.
9. Zoom Anchor Centering: Viewport-center zoom calculation (superseded by Fix 37 cursor-focal zooming and interpolation).
10. Oversized Editor for Small Snips (root cause): ImageEditorWindow.axaml declared MinWidth=850 MinHeight=650 and PositionWindow mirrored those numbers, so even a 300x200 snip opened in an 850x650 shell. Fix: XAML declared minimums set to MinWidth=880 MinHeight=630 with programmatic layout minimums MinEditorWindowWidth=880 MinEditorWindowHeight=520, and AutoFitWindowToContent corrects estimated chrome with real ScrollViewer viewport after first layout pass.
11. Pro Color Picker: CustomColorBtn flyout rebuilt as a dark panel - ColorView spectrum + shades, live two-way HEX entry (#RRGGBB / RRGGBB / #AARRGGBB, Enter applies), copy-hex-to-clipboard button (plain text), live preview chip, and the retained screen sampler.
12. Emoji Flyout Not Closing (root cause): OnEmojiSelectClick updated tool state but never closed the EmojiTool flyout, leaving the popup dangling over the canvas while the ghost floated the selection. Fix: emojiBtn?.Flyout?.Hide() runs as the final step of the click.
13. Stale Marching Ants (root cause): OnToolClick only released the selection when a PASTED IMAGE was selected; picking a new tool while a normal annotation was selected left _selectionIndicator (and handles + context toolbar) glued to the old object. Fix: any tool activation now clears _selectedControl and refreshes the indicator, mirroring the empty-canvas deselect path.
14. Broken Scrollbar Visuals (root cause): the Fluent ScrollBar template renders a translucent auto-hiding overlay thumb with no arrows - near-invisible on the #1E1E1E canvas. Fix: DesignSystem.axaml now ships FreeSnipScrollBarVertical/Horizontal ControlThemes (solid rounded thumb with hover/press states, sunken track, chevron arrow buttons) and ImageEditorWindow.axaml applies them to EditorScrollViewer while keeping AllowAutoHide=False.
15. Sluggish Final Action / Overlay-Editor Drift (root cause): OnDownloadClick/OnCopyClick/OCR awaited a HARDCODED Task.Delay(1000) before closing the editor while the blink overlay honoured NotificationOverlayDurationMs - at a 500ms setting the editor idled 500ms after the blink was already gone, and long settings left the overlay blinking alone long after the editor closed. Fix: NotificationOverlayWindow.GetOverlayDurationMs() is the single source of truth; the editor clamps it to [250, 1000] for its close wait (never slower than the old fixed second, faster for any shorter setting). Overlay lifetime hardened too: the heavy blink and light toast windows close in finally, and the light-toast _activeToasts counter is decremented on every path (a thrown fade used to leak the slot and permanently offset later toasts).
16. Mixed-DPI Cross-Monitor Rubberband (root cause): freesnip.manifest opts into PerMonitorV2, under which EVERY top-level window carries exactly ONE DPI factor (the monitor that owns it), so the single virtual-desktop overlay from fix #7 could only map DIPs to device pixels correctly on its owning monitor - on mixed-DPI setups the rubberband was pixel-exact only on the screen where the drag started and drifted off the cursor or vanished on the other screen(s). Fix: CaptureRegionAsync slices the unified frozen backdrop per monitor and spawns one CaptureWindow PER MONITOR (each window lives entirely inside a single screen, so its DPI factor is exact), while CaptureWindow keeps the selection state in ABSOLUTE device pixels and broadcasts the rubberband + dimension badge, snap highlight + badge, alignment guides and magnifier ownership to the sibling overlays (ForEachOtherOverlay/ApplyShared*), each converting through its own Position/Scaling. The drag owner retains Win32 mouse capture across borders, the lens hands over to whichever monitor is under the cursor, the snap state is mirrored everywhere so C-copy works from any overlay, and leaving the snap zone mid-drag now clears the stale highlight.
17. Editor Zoom Drift Resolution: Top-left zoom anchoring investigation (superseded by Fix 37).
18. Editor Magnet Unreleasable While Resizing (root cause): the resize handles snapped the dragged edge to EVERY other shape's edges plus the image borders using the same wide 12-DIP capture zone as whole-shape moves - while enlarging, the dragged edge sweeps across many such targets, so escaping one capture (dragging 12 DIPs past it) dropped the edge straight into the next target's zone, which felt impossible to override mid-drag. Fix: resize handles now use a tighter 6-DIP capture zone (half the move zone, so an escape takes half the pull), and holding ALT is a LIVE magnet override on every snap path - resizing handles, dragging whole shapes, stretching new shapes and dragging line/arrow endpoints all follow the pointer raw while ALT is held and re-engage snapping the moment it is released (Shift's strict-angle mode still wins for vectors). The snap-dot indicator also hides while ALT is held so it never advertises a snap that is being overridden.
19. Region Capture Crashing With InvalidCastException (root cause, introduced by fix 16): the per-monitor overlay rewrite cloned the unified frozen backdrop with a hard (Image<Rgba32>) cast - but NativeCapture produces Image<Bgra32>, and casting one closed generic to another compiles fine (both derive from the non-generic Image base) yet ALWAYS throws InvalidCastException at runtime, killing every region capture ~50ms in (log: "CaptureRegion failed." / Arg_InvalidCastException) before any overlay appeared. Captures had been broken on the shipped builds since fix 16 shipped. Fix: the clone now goes through Image.CloneAs<Rgba32>(), which performs a real Bgra32->Rgba32 pixel conversion and returns a genuine Image<Rgba32> - the same conversion pattern OcrImagePreprocessor already uses safely.
20. Resize Magnet Still Trapping Without ALT (root cause left by fix 18): the fix 18 resize snap computed each frame's magnet from the shape's ALREADY-SNAPPED bounds (left/oldW read back from the control after the previous snap), so every snap shifted the baseline - the effective capture zone stretched past the pointer, on release the edge jumped ahead of the cursor, and crossing back re-captured, chaining into an unreleasable loop only ALT could break; there were also NO guide rails while resizing, so the pull was invisible and read as a stuck cursor. Fix: resizing now runs through the EXACT same engine as dragging/placing whole shapes - a raw, never-snapped bounds accumulator (_resizeUnsnappedLeft/Top/Width/Height, the resize twin of _dragUnsnappedLeft/Top) is advanced by the pointer deltas each frame (opposite edge anchored; at the 10-DIP floor the dragged edge simply freezes, no hysteresis), and only the APPLIED bounds get bent by the new ApplyResizeMagneticSnap: the dragged edge snaps to any edge-or-center rail of every other shape plus the image frame (the identical candidate set TrySnapAxis uses for moves), the pull is capped at the shared 12-DIP VectorSnapThreshold, it releases the instant the raw edge leaves the zone, and the same dashed guide rails as the move magnet appear so the snap is gentle yet FELT. ALT stays a live raw override, the toolbar magnet button (MagneticSnappingEnabled) remains the user-facing toggle, and double-pressing a handle still flips snapping for that drag. The orphaned SnapAxisEdge/GetMagneticSnapTargets helpers and the ResizeSnapThreshold const were removed.
21. Toolbar UI Polish: Added 3D indented bevels to all toolbar buttons, applied Opacity="0.35" to disabled buttons, and softened the active-tool highlight to a 40% transparent blue (#660078D7). The Pixelate slider was narrowed to 140px, the Clear All button inherited the 'destructive' 3D style and its nuclear SVG was set to Stretch="Uniform", the redundant "Colour" label was removed to save space, and the Arrow SVG was centered with a leftward margin adjustment.

    - Fix: Replaced full-row downsampling with a tile/block-based motion estimation engine in ScrollCaptureRecorder.cs. Divides captured frames into an 8x8 grid of analysis blocks, estimates candidate translation vectors (dx, dy) per block, and uses consensus voting (EstimateGlobalMotion) to identify the moving viewport while rejecting stationary chrome blocks (dx=0, dy=0). Line-by-line boundary refinement (RowAverageDiff, ColAverageDiff) isolates the exact scrolling viewport rectangle. The stitching compositor (BuildImage) keeps stationary ribbons, headers, footers, and sidebars fixed in place while stitching newly revealed document slices. Added tracking re-acquisition against _recentFrames buffer to recover from jump scrolls or transient occlusions.

101. Scroll Capture Overlap Verification & Axis Consensus Stitching Fix:
    - Root Cause Analysis: In ScrollCaptureRecorder.cs, AddFrame() permanently locked the scroll axis (_isVerticalScroll, _scrollAxisLocked) from a single first-frame coarse motion estimate. A noisy initial estimate (e.g. DeltaX=22, DeltaY=5) could misclassify a vertical webpage as horizontal, producing abnormally wide composites. Additionally, AddVisibleStrips() blindly trusted coarse EstimateGlobalMotion/EstimateViewportMotion deltas as exact pixel-level ground truth, using Math.Abs(deltaY) directly as strip height. Even 1-3px motion estimation errors produced duplicated or missing pixel rows at every seam in the final stitched image.
    - Overlap Verification Engine: Added VerifyOverlapDisplacement() as a second-stage pixel-overlap verifier in ScrollFrameStitcher. For each accepted frame, the method searches ±3px (OverlapSearchRadius) around the coarse displacement estimate within the detected _viewport rectangle, scoring each candidate using the same normalized SAD metric (ComputeAreaSad) already used by the motion estimator. A slight bias toward the coarse estimate (0.05 per pixel of deviation) breaks ties. The displacement producing the lowest verified SAD score is used for offset accumulation and strip cropping. If no candidate meets the confidence threshold (OverlapConfidenceThreshold = MaxTileSad), the frame is rejected and routed to the existing re-acquisition path rather than committing an uncertain seam.
    - Axis Consensus Locking: Replaced single-shot axis locking with a 2-consecutive-vote consensus mechanism (UpdateAxisConsensus). Both _consecutiveVerticalVotes and _consecutiveHorizontalVotes must reach their threshold before the axis is locked. Horizontal locking additionally requires Math.Abs(verifiedDx) >= 20 and 3:1 dominance ratio. An optional AxisHint property (set from ScrollCaptureWindow.axaml.cs mouse wheel intent) counts as a pre-existing vote, reducing the threshold to 1 for the hinted axis while maintaining full pixel-overlap verification as authoritative.
    - Integration Points: All four acceptance paths in AddFrame() (initial viewport detection, viewport motion, global fallback, and re-acquisition) now route through VerifyOverlapDisplacement before committing strips. Failed verification falls through to the next path or re-acquisition rather than committing uncertain seams. ScrollCaptureWindow.axaml.cs sets Recorder.AxisHint = true after instantiation to communicate vertical mouse wheel intent.
